# Conclusión 
Luego de haber ejecutado los programas `analizar.py` y `exportar_history.py`, y de chequear los archivos generados, logramos determinar que el modelo descubierto no es muy similar al modelo bpmn del proyecto, primero se logra observar que el orden de las tareas no es el mismo a las del modelo, aunque llevan el mismo nombre no siguen el mismo orden lógico de aparicion, difieren las compuertas logicas, y por ejemplo, no existe un join entre las tareas reservar aula, preparar materiales y solicitar aula virual, tampoco siguen el mismo orden logico ya que son actividades que se realizan en paralelo, de todos modos el analisis está muy limitado ya que se necesita de un historial ámplio con flujos que pasen por las distintas ramas posibles, como para poder generar una historia rica que nos sirva para hacer este análisis, en nuestro caso, por diferentes problemas durante el desarrollo, se tuvo que re-deployar el motor o bajar y subir el contenedor donde se aloja flowable, por lo que ibamos perdiendo la historia de ejecuciones anteriores, probablemente con varias ejecuciones seria posible un mejor análisis del historial.
